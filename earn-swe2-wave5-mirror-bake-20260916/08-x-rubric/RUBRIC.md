# RUBRIC — X 投稿の仕分け（AIエージェント外注）

対象: [`KEYWORDS.md`](KEYWORDS.md) のクエリで人が開いた **Latest** の投稿。1行ログの型は末尾。返信ドラフトはこのフォルダに無い。送るのは人、別パック。

判定は **fail-closed**。迷ったら `skip`。`keep_queue` は「あとで人が個別に返す候補」であり、返信許可ではない。

---

## 1. 3値だけ使う

| 値 | 意味 | 次の手 |
|---|---|---|
| `keep_queue` | 発注者っぽい + この机の仕事 + 直近 + 売り手ではない | 秘密なしログ。返信は人が下書き。この PR では送らない |
| `park` | 興味はあるが依頼になっていない。または技術が広い | 再検索のときだけ見る。営業しない |
| `skip` | 売り手・求人板・範囲外・詐欺・古すぎ・複製宣伝 | ログして終わり。反論しない |

`needs_check` は使わない。X の本文は今読める。読めない（削除・鍵アカ・言語不明）は `skip`。

---

## 2. keep_queue に必要な4点（全部）

欠けたら keep にしない。

1. **Buyer** — 相手が仕事を頼みたい側。自分のギグを売っていない。
2. **Fit** — 本文が [`KEYWORDS.md`](KEYWORDS.md) §0 の箱（n8n / 公式 API / 依頼票と検品 / GAS / 人が止まれるエージェント）のどれか。
3. **Shape** — 業務委託・外注・単発・短期。正社員応募・現地常駐のみ・無給試用は不可。
4. **Fresh** — 目安 **7日以内**（`{{SINCE}}`）。それより古い「まだ探してます」は `park`。スレが「決まりました」なら `skip`。

加えて **具体が1つ**あること。無いなら `park`。

具体の例（これがあれば足りる）: ツール名、今手でやっている手順、壊れている箇所、成果物の種類（フロー1本、検品、手順書）、期間。

金額・会社名・実名は **keep の条件にしない**。ログにも写さない。

## 3. 即 skip（1つでも当たれば）

| 型 | 見た目 | 理由 |
|---|---|---|
| seller | 「作ります」「I build AI agents」「slots open」「DM for rates」 | 同じ机の競合または宣伝 |
| bait | 「誰でもAIエージェントで月収」「1000 agents」 | 情報商材・釣り |
| job board | Apply / Lever / Greenhouse / 正社員 / 新卒 / ビザスポンサー | 求人。業務委託机ではない |
| out of scope | いいね自動化、スクレイピング、非公式 SNS 操作、鍵を預かれ | 兄弟 HANDS と同じ範囲外 |
| crypto / adult | エアドロ、NFT、トレードボット、成人向け | 扱わない |
| scrape-me | リンク先が「案件一覧スクレイプ」や一斉 DM 勧誘 | 使わない |
| copy-paste mill | 同じ英文が複数アカ、短縮URL連打 | ボット |
| too old | 2週間超で結論なし | もう埋まっているか放置 |
| locked | 鍵アカ・削除・表示不能 | 追わない |
| unpaid | 「経験のため無償」「equity only」で現金なし | 受けない |
| KYC / 審査代行 | 本人確認を代行してほしい | 停止。アップロードもしない |

「フルタイム可、業務委託も可」は、本文がリモートのプロジェクトなら keep 候補。応募フォームが Jobs のみなら skip。

---

## 4. park（keep にしない）

- 「エージェント気になる」「n8n 勉強中」だけで頼んでいない
- ChatGPT 一般論、ニュースQT、論文リンク
- ツール比較の質問（「Make vs n8n どれ」）で発注が無い
- 紹介してほしいが、何を作るか無い
- 英語の採用ブランド投稿を日本の個人が返すのが不自然（大企業 HR）
- 予算ゼロ宣言だが相談だけ

park はフォロー自動化の理由にしない。通知を足すなら人が手動の検索保存だけ（有料 X Pro は買わない指示を書かない。既に持っている人の列追加は任意）。

---

## 5. 本文の読み方（短く）

上からこの順。時間をかけない。

1. 誰が主語か（I need / 作ってほしい vs I offer / 始めました）
2. 動詞は発注か宣伝か
3. 技術は §0 か範囲外か
4. 成果はフロー・コード・手順書か、フォロワーか
5. 場所（リモート可か、週5出社のみか）
6. 日付（UI の相対時刻。ログには `seen_at` と UI の相対表示だけ。投稿 URL は公開 permalink のみ可。本文全文は git に貼らない）

引用リポストは **引用側の文** で判定する。元が求人で引用が「誰か受けない？」なら引用側を Buyer として見てよい。

## 9. 秘密なしログ（git / チャット用）

1行。本文全文・金額・実名メールを載せない。

```text
date: {{YYYY-MM-DD}}
query_id: {{Q-EN-01}}
permalink: {{PUBLIC_STATUS_URL_OR_EMPTY}}
lang: {{ja|en}}
gate: {{keep_queue|park|skip}}
buyer: {{yes|no|unsure}}
fit_box: {{n8n|agent_inspect|official_api|gas|other_skip}}
shape: {{freelance|job_board|seller|unknown}}
fresh: {{ui_relative_or_unknown}}
one_detail: {{ONE_NON_SECRET_DETAIL}}
next: {{human_draft_reply|none}}
```

`unsure` は keep に使わない → `skip` か `park`。`permalink` が空でもよい（コピーしなかった）。空のまま想像で埋めない。
