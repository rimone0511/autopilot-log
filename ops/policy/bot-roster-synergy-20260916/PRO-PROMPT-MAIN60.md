### 2.2 Grok Bot の製品事実（公式 Docs 由来。ここに無い機能は設計に使わない）

出典: docs.x.ai の `grok-bot/overview`、`grok-bot/bots`、`grok-bot/chat-and-collaboration`、`grok-bot/skills-routines-and-automations`、`grok-bot/faq`（2026-09-15 閲覧）。

- **Bot** は名前・職務・自分の会話・時間とともに育つ作業文脈を持つ恒久的なチームメイト。**description は「ずっと真であるべきルール」の置き場**、会話は個別の指示。例: description「承認なしに外部へ送信しない」、会話「この 12 件の下書きを作れ」。
- **グループチャット**は **2〜6 Bot**。`@` で名指しすると、その Bot が担当。名指しせず普通に書くと **参加 Bot 側が誰が答えるか決める**。複数名指し可。`@everyone` は控えめに。「各段階の所有者は 1 人にせよ。並列の手渡しが多いと重複作業と騒音になる」。
- **Bot 同士の非同期手渡し**がある。送られた Bot が起き、処理し、後で返す。**手渡しは会話に見える形で残る。** Bot→グループの手渡し文は現状テキストのみ。
- **スレッド**は 1 つの結果や承認要求への追記に使う。**リアクションは軽い了解。安全上の決定をリアクションだけで運ばない。**
- **Bot が見えるのは自分が参加している会話だけ**（自分の 1:1、所属グループ、直接の手渡し）。**他の 1:1 を黙って読む機能は無い。**
- **記憶は Bot ごとに別。** 安定した好み・重要事実・作業要約を保持。「記憶は正本の代わりではない。重要な決定では現在の出典を見直させよ。安全境界は description に明記せよ」。
- **スキル**は全 Bot 横断で使える（Bot ごとに有効化）。**ルーチンは 1 Bot が所有**し、スケジュールまたはイベントで起動。Bot を削除するとルーチンも消える。**使わない Bot は非表示にせよ。**
- **全 Bot が 1 台の永続クラウド計算機（ブラウザ・ファイル・ターミナル）を共有。** ファイル・ブラウザセッション・ログインも共有。**Bot は隔離境界ではない。** 各 Bot は自分の画面を持ち、1 Bot は同時 1 本の CU。
- **Bot の複製**は profile・設定・有効スキル・ルーチンを写すが、会話履歴・学習記憶は写さない。
- **Bot の共有リンクは公開。** description・スキル・ルーチンの構成が誰にでも見える。
- アカウント上限は Bot＋グループ合算で約 50。**使用量は週次でリセットされる共有の枠**（Cursor 有料プランに含まれる）。枠の実数はここで断定しない。
- **Bot を動かすモデルの種別は Docs に明記なし。** 本相談では「全席が同クラス」と仮定して設計する（同型でも効く設計は、異型ならさらに効く）。
- 公式の推奨: 「最小の有用な席次から始める。1 Bot に端から端までの成果を持たせる。安定した専門役がある時だけ Bot を足す。手渡しそのものが見える必要がある時だけグループにする。外部への行動は明確な承認境界の内側に置く」。

### 5.1 相乗の理論（同型モデルを「別の頭」にする 5 つの差＋1）

相乗は「意見の数」ではなく、**直交する損失関数 × 異なる証拠 × 強制された統合**。席ごとに次を違える。5 つが同じなら名前を変えても同じ Bot。

| 差 | 何を違えるか |
|---|---|
| 1. 目的関数 | 最大化・最小化するもの。崩し=壊すコストの最小化 / 外の目=買い手の理解と信用 / 三案=案の機構の多様性 / 窓口=決定までの祐太の負荷 |
| 2. 禁止 | 絶対に言わないこと。崩しは修正案を書かない / 外の目は内側の言葉を使わない / 三案は評価しない / 窓口は議論に参加しない |
| 3. 証拠の食事 | その席にだけ渡す材料。崩し=ロック・FACTS・DoD・過去 SOL 所見の型 / 外の目=対外物そのもの＋ペルソナカード / **三案=問いと制約だけ（現行案を見せない＝アンカー除去）** |
| 4. 出力の型 | 固定フォーマットと上限行数 |
| 5. 発言トリガー | いつ話し、いつ黙るか |
| ＋ 記憶の分業 | Bot ごとに別の記憶（製品事実）。崩しは「壊れ方の型」、外の目は「買い手の引っかかり」を相談横断で蓄積。窓口の制御記憶と混ぜない |

- 決定の記録（書記スキル）: 決定・却下・保留・昇格を Notion 共有記憶と repo に残す。

### 5.4 部屋の運用案

- **Tier:** Tier 0 = 祐太 ↔ 窓口 1:1（不変）。Tier 1 = 詰め所（Grok グループ）。Tier 2 = 外部モデル（Fable → Pro / SOL / SWE-2）。詰め所は Tier 2 の代わりではない。
- **部屋は常設 1 つ。** 相談ごとに作らない（記憶の蓄積と、祐太の見る場所を 1 か所にする）。長期案件だけ別部屋を検討。
- **手渡しの型は「見える手渡し」（グループ投稿）。** Bot 間の直接手渡しは、窓口→記録など祐太が見る必要の無い雑務だけ。
- **一日の流れ:** 朝、窓口がルーチンで 1:1 に看板 1 枚（詰め候補 ≤3、昨日の決定 ≤3、待ち ≤3）。祐太は番号で選ぶ。日中、窓口が詰め札を詰め所へ。席が各 1 回返す。必要なら R2 を 1 回。窓口が裁定し 1:1 に 7 行カード。祐太は決定語で返す。夕、窓口が記録。
- **決定語（固定）:** `GO` / `NO-GO（理由 1 行）` / `保留` / `Fableへ` / `Proへ` / `SOLへ`。リアクションは「読んだ」だけで、決定に使わない。
- **ラウンド規則:** R0 起票（窓口）→ R1 応答（名指しされた席が各 1 回。名指しされずトリガー未達の席は投稿しない）→ R2 反論（割れた時だけ、窓口が 1 回だけ再照会）→ **R3 は無い。** 畳めなければ「Fableへ」。追記はスレッド。
- **詰め札テンプレ（Fable 案）:**

```
【詰め札】相談ID: {ID} / 版: v{n}
公開・送信・適用・登録は禁止。ここは詰めの場。
問い（1 行）:
前提・ロック（貼る）:
対象（貼る。対外物なら本文そのもの）:
ペルソナ（外の目用。既定: JP 小規模事業者）:
呼ぶ席: @崩し（必ず） / @外の目（対外物あり） / @三案（案が要る時）
---- 席の返答（各 1 回） ----
崩し:
外の目:
三案:
---- 窓口の裁定案 ----
採る / 捨てる / 保留（各 1 行）:
祐太への問い（1 つ）:
昇格: なし / Fableへ / Proへ / SOLへ
```

- **費用のつまみ:** 黙る席を作る（三案は呼び出し、外の目は対象がある時だけ、崩しは 1 回）/ 証拠は貼る、探させない / ラウンド上限 2 / 枠が切れた週は切れた曜日と詰め札枚数・席投稿数を記録。割合は書かない。

### 5.5 パイロットと kill 案

- **範囲:** 実在の次の 5 相談（例: P4 手順書の形、P5 器 README 先頭、Coconala カバー・画像 3 枚の構想、Gumroad 買い手向け README、次に Pro へ投げるプロンプトの研ぎ）。架空の練習相談は作らない。
- **測る（件数で）:** 崩しの異議のうち「採る」になった数 / 外の目の一言で変わった決定の数 / R2 に入った件数 / 昇格（Fable・Pro・SOL）の件数 / 祐太が詰め所を直接読んだ回数 / 週の枠が切れた曜日。
- **見直し点:** 5 相談目の裁定後、窓口が観測値を 1 枚にして祐太へ。続行・入替・縮小を決定語で。
- **kill（席ごと）:** 崩し=5 相談で「採る」異議 0 → チェックスキルに移して非表示。外の目=5 相談で決定が変わらない → ペルソナ替えで 3 相談再試行、それでも 0 なら非表示。三案=呼ばれず、または採られない → 呼び出し停止、01 案は Fable 上流へ戻す。部屋全体=祐太が詰め所を直接読まないと決められない状況が 2 回 → 詰め札を短くする、直らなければ 1:1 に戻す。枠が Hands より先に切れた → 三案→外の目の順で沈黙、崩しだけ残す。

## 7. 書き方の規則

1. **決め切る。** 「A か B が考えられる」で終わらせない。証拠不足は仮決め＋「要確認」印＋確認手順。
2. **製品事実は §2.2 の範囲で。** それ以外を前提にする時は「要確認」印。
3. **数字を発明しない。** パーセント・推定工数・削減率を書かない。上限行数・人数・ラウンド数などの**設計値**は書いてよい（設計値と観測値を混ぜない）。
4. **ロックを再定義しない。** §2.1 の順序・必須性・禁止はそのまま。詰め所はその下位工程。
5. **祐太に見せる文面は短く。** 決定語、看板、7 行カードは実際に貼れる文で。
6. **憲法は貼れる文で。** 見出しや箇条書きの説明ではなく、description にそのまま貼れる文章体。短い版と標準版。
7. **日本語。** 外の目が EN 案件を読む時の言語の扱いは §2 で明記。
8. **同じことを二度書かない。** 参照は「§n を見よ」で。
9. **1 通で完結を目指す。** 切れる場合は「続きます（§n から）」と書いて止め、続きの冒頭に §n を再掲する。
