現時点の判断は、**全面実行は NO-GO、需要との対応を確認した最小ショーケースだけ条件付き GO**である。

## 2. n8n-first / Coconala-first / P1-first への最強の反証

### 2.1 n8n-first

**最強の反証:** n8nは買い手の課題ではなく、導入後に版管理、認証、ホスティング、実行監視、引継ぎを発生させる運用選択である。模擬接続とローカルCSVが動いても、実サービスのOAuth、権限、レート制限、障害復旧を納品できる証拠にはならない。n8n指定でない顧客へ先にツールを固定すると、簡単なスクリプトや表計算で済む仕事まで重くし、1万円範囲との矛盾を強める。

さらにFable報告が正しければ、現在の公開証拠はPython/SNS自動化寄りで、n8n実物は未公開である。n8nへ寄せることは既存信用の転用ではなく、新しい証拠づくりである。この証拠ギャップを「n8n案件がありそう」で正当化してはいけない。

**成立条件:** 限定観測した適合候補の中に、n8n指定またはn8n許容で、外部接続を伴わない小さな受入条件が複数あること。顧客または発注者が運用環境を持ち、引継ぎ責任を合意できること。

**falsifier:** 最大12件の適合候補を確認しても、n8n指定/許容かつ小規模な候補が3件未満なら、初回の「n8n-first」を外す。これはn8n市場全体の否定ではなく、この実行周期のwedge不採用である。

### 2.2 Coconala-first

**最強の反証:** 出品面は販売経路ではあっても、需要獲得の証拠ではない。画像を埋めて公開できることと、適合顧客が検索・相談することは別である。Pro記載の22%手数料が当該取引にも適用されるなら、1万円からの対応余力はさらに狭くなるが、今回その現行条件は再確認していない。

非技術の買い手が求めるのがGmail、Sheets、LINE等との実接続なら、ローカルCSVの安全なデモは「n8nを触れる」証拠にはなっても「欲しい納品物」の証拠にはならない。逆にn8n指定の買い手なら、一般出品より専門募集の方が課題との距離が短い可能性がある。ゆえにココナラ主軸は、現行出品が存在するというサンクコストだけでは決められない。

**成立条件:** 現行状態を許可された方法で確認でき、追加支出なしで出品/提案準備ができ、P1の範囲に合う具体的な相談導線または募集があり、手取りと追加対応を含むスコープが成立すること。

**falsifier:** 比較対象2チャネルのうち、ココナラに具体的な適合候補がない、公開までの摩擦が高い、または1万円範囲では要求される接続・修正・サポートを収められない場合、主軸指定を解除する。

### 2.3 P1-first

**最強の反証:** Pro版P1は、入力検査、永続重複制御、衝突判定、分類、返信下書き、確認待ち、実行記録、動画、図、配布物まで含み、1つの最小見本ではなく複数の価値仮説である。どれが買い手に必要か分からない段階で全部を実装すると、「高品質な未検証商品」を作る危険が高い。

特に返信下書きは、文面品質、誤送信、個人情報、AI利用、承認責任への期待を増やす。一方、問い合わせ整理だけならn8nが過剰になり得る。P1を先に固定するより、具体的な候補の受入条件から一番短い縦切りを選ぶべきである。

**成立条件:** 限定観測した候補に、入力検査、重複/衝突の可視化、確認用一覧の少なくとも2要素が繰り返し現れ、外部送信や本番認証なしの証拠でも提案に使えること。

**falsifier:** 最大12件の適合候補中、P1形状の課題が3件未満ならP1を作らない。P1着手後4時間で「新しいfixture→実n8n→期待出力」の縦切りが通らなければ機能を削り、8時間で下記Mustパックが揃わなければ初回P1を止める。

## 3. Minimum Viable Showcase

### 3.1 初版の1本

名称（内部）: **S0「問い合わせ入力を、処理済みと要確認に分ける」**

```text
合成入力
  → 必須項目と形式を検査
  → 同一内容の重複 / 同一IDの衝突を区別
  → accepted.json(or csv) + review.json(or csv)
```

初版から外すものは、AI分類、返信下書き、メール/Slack/Sheets/CRM接続、通知NoOp、承認Webhook、ダッシュボード、週報、長編手順書、動画、Gumroad ZIP、公開repo、ブランドキットである。

fixtureは、正常、完全重複、同一ID異内容、必須欠損、不正形式を含む少数の合成データにする。件数自体を品質や性能の主張に使わない。永続的な重複防止を実装・再現できない場合は、「重複を検出して別出力にする」とだけ主張し、「二重登録を防ぐ」とは書かない。

必要資産は次の6点だけである。

1. 固定した対象n8n版でimport可能かつinactiveなworkflow JSON
2. 合成fixtureと、人が読める期待出力
3. 実行手順、含む/含まない、検証範囲をまとめた1ページREADME
4. 実行記録（対象版、入力ハッシュ、結果、失敗ケース、実行日時）
5. 表紙、結果、要確認/範囲の静止画3枚
6. 別担当が空の作業領域から再現した記録

### 3.2 Must-only quality bar

| 観点 | Must |
|---|---|
| 買い手適合 | 許可された根拠から確認した具体的な適合候補1件以上に、同じ入力・出力・除外範囲で提案できる。候補がなければ制作GOを出さない。 |
| 実動作 | 固定n8n版でimportし、新しいfixtureから期待した2出力を得る。予定ではなくコマンド/実行記録を残す。 |
| 失敗の扱い | 欠損、形式不正、重複、衝突を成功件数へ混ぜない。結果不明を成功表示しない。主張する場合だけ再実行試験を必須にする。 |
| 安全 | workflowはinactive。外部送信・決済・投稿・本番コネクタを含まない。停止方法がREADMEにある。 |
| 秘密/個人情報 | 合成データのみ。鍵、URL、webhook path、実ID、認証画面、顧客データをworkflow、log、画像、動画に含めない。 |
| 再現性 | 作者とは別の担当が、空の作業領域でREADMEだけを使い、import→実行→期待出力確認まで到達する。 |
| 正直な表示 | 「自主制作」「合成データ」「模擬/ローカル出力」「顧客実績・時短・売上・精度の証拠ではない」を近接表示する。 |
| 販売範囲 | 誰向け、入力、出力、納品物、対象外、追加費用条件、修正回数、保守なし/あり、価格の適用条件が1ページで矛盾しない。 |

## 5. 登録拡大

### 判断

**現時点は NO。新規登録上限は0件。**

登録を再開できるのは、次をすべて満たす場合だけである。

- S0のMustが合格し、少なくとも1回の公開または適合案件への送信が本人GOのもとで実施済み
- 現行2販路では到達できない具体的な適合候補がある
- 追加先が無料で、規約と応募条件を確認でき、既存素材を流用できる
- 登録後48時間以内に、その候補向けの個別提案下書きを作れる
- 第3販路を増やすのではなく、既存の能動枠1つと交換する

### caps

| 対象 | 上限 |
|---|---|
| 能動営業販路 | 同時2 |
| 新規登録 | 14日で1件、30日累計2件 |
| 登録作業 | 1サイト45分まで、30日で合計2セッションまで |
| 有料化 | 0。課金が必要なら停止して別判断 |
| 同時受注 | 初期は1件。納品負荷を確認する前に並行受注を増やさない |

### kill criteria

- 具体的な適合候補が消えた、募集終了、または必須経験を満たさない
- 15分同じ画面で進まない、異なる2手段でも進まない、または合計45分で`draft_saved`相当へ届かない
- KYC、captcha、本人専用認証、所在地不一致、追加課金、規約不明が出る
- 認証回避、別アカウント、非公式自動化、無断収集が必要になる
- 登録後48時間以内に個別提案へつながらない
- 30日内に維持・通知確認だけが増え、適合提案に使われない

停止はそのサイトの優劣を断定するものではない。登録作業を収益成果として数えないための運用上のkillである。

## 7. 仮説ごとのfalsifier

| 仮説 | 反証観測 | 判断 |
|---|---|---|
| H1: n8nが初回wedgeに合う | 最大12件の適合候補で、n8n指定/許容かつ小規模候補が3件未満 | n8n-firstを外し、既存証拠に近い実装またはdocs診断と比較する |
| H2: Coconalaが主軸に合う | 適合候補なし、現行状態/費用不明、要求範囲が1万円極小範囲を恒常的に超える | 主軸指定を解除し、能動2枠を交換する |
| H3: P1形状が買い手課題に合う | 最大12件中、入力検査・重複/衝突・確認一覧の組合せが3件未満 | P1を作らず、最頻の具体課題からS0を引き直す |
| H4: 1万円ミニ導入が成立する | 最初の実質相談3件がいずれも、本番接続、設置、継続保守など対象外を必須とする | 1万円の「導入」を止め、診断/仕様化または個別見積りへ変更する |
| H5: 品質不足が応募を止めている | Mustが全緑でもShould/Niceを理由に下書きが送信GOへ進まない | 追加制作を停止。残る問題は品質ではなく、承認・チャネル・商品仮説として扱う |
| H6: 現行訴求で対話が生まれる | 適合提案を実送信し、到達確認できたものを中心に10件程度、過半の送信から7日以上で実質返信なし | 対象、課題表現、販路のうち1つだけ変更する |
| H7: 第2試行でも有料範囲へ進む | 1変数を変えた第2試行を含む累計最大20件程度でも有料範囲の相談なし | 新規登録と新作を止め、商品を再設計する。市場不存在とは断定しない |

実質返信は、課題、範囲、予算、納期、実装条件のいずれかに触れる相手の反応を指す。自動返信、閲覧、登録完了、下書き、未送信、到達不明は成果に数えない。

## 8. Execution前 GO / NO-GO checklist

### 制作GO

- [ ] B2の限定候補に、S0と同じ入出力で提案できる具体例が1件以上ある
- [ ] n8nを使う理由が「作りたいから」ではなく、案件指定、引継ぎ、変更容易性のいずれかで説明できる
- [ ] n8nを使わない方が単純な場合に、実装手段を変更できる
- [ ] S0の対象外（AI、返信、通知、実接続、保守、動画、ZIP）を受け入れている
- [ ] 固定版、空の再現領域、ファイル移送、証拠保存の経路が追加費用なしで使える
- [ ] 作者と独立再現者が分かれている
- [ ] 4時間/8時間のstopを受入カードに記載した

上記のどれかが欠ければ制作は **NO-GO**。ただし、Should/NiceがないことはNO-GO理由にしない。

### 公開・応募GO

- [ ] S0のMust-only quality barが全項目合格
- [ ] workflow、fixture、期待出力、README、実行記録、静止画3枚が同じ版
- [ ] 合成データ、自主制作、模擬/ローカル範囲、未検証点を近接表示
- [ ] 画像・添付・メタデータ・logを含め、秘密と実個人情報がない
- [ ] 対象チャネルの現行規約、費用、公開状態、外部誘導制限を許可された方法で確認
- [ ] 価格、含む/含まない、修正回数、追加費用、保守、納期の根拠を本人が確認
- [ ] 宛先/公開先、本文、添付、価格、回数、実行担当を特定
- [ ] 同じ対象への送信履歴を照合し、重複でない
- [ ] 公開、応募、送信ごとの明示的な本人GOがある
- [ ] signup、KYC、captcha、課金、認証回避、非公式自動化を伴わない

1項目でも欠ければ外部実行は **NO-GO**。結果不明時は再クリックせず照合する。今回の範囲では、公開、応募、signup、ブラウザCUは行わない。

## 9. 10行の最終推奨

1. 現時点は全面実行NO-GO、需要対応を確認した最小実証だけ条件付きGOとする。
2. n8nは既定路線でなく、具体案件が指定または許容する時の実装候補に下げる。
3. ココナラは主軸固定せず、適合候補と利用摩擦で能動2販路を選び直す。
4. P1は返信下書き・AI・通知を外し、入力検査と要確認出力のS0へ縮める。
5. Mustは実動作、失敗の非成功表示、秘密なし、正直な範囲、独立再現だけに絞る。
6. Cursor Grokが初版資産を作り、SWE-2が別環境で再現・実画面を検品する。
7. 4時間で縦切り未達なら削り、8時間でMust未達なら同じP1を止める。
8. 新規登録は今は0件、再開後も1件/14日・2件/30日・能動2販路までとする。
9. 適合提案10件前後で無反応なら1変数だけ変え、累計20件前後で商品を再設計する。
10. P2、P3、Gumroad、動画、公開repoは初回提案を待たせず、反応が示した1件だけ開く。
