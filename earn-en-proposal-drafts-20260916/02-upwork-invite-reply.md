# 02 — Upwork invite reply

| | |
|---|---|
| Desk | Upwork |
| Type | Invite reply |
| Mode | DRAFT_ONLY, HANDS paste |
| When | A client invited you to a job; you reply in the invite / Upwork Messages flow |
| When not | Cold apply (use 01). Off-platform email the client sent you (do not continue there; stay on Upwork and report if needed) |

An invite is not a contract. It is not permission to share contact details. Interview still stays on Upwork for ordinary clients ([contact-info help](https://support.upwork.com/hc/en-us/articles/360051749534-How-to-keep-your-contact-information-safe-on-Upwork)).

Connects on invites vary. Read the form. This pack does not tell you the cost.

## Send gate

- [ ] I opened the **invite** in Upwork, not a forwarded Gmail thread
- [ ] `{{ONE_SPECIFIC_DETAIL}}` comes from the job text they invited me to
- [ ] I am willing to do this work (if not → snippet 08)
- [ ] No Means of Direct Contact in this reply
- [ ] I click send myself

## Paste

```
Thanks for the invitation on "{{JOB_TITLE}}".

I read {{ONE_SPECIFIC_DETAIL}}. That is in scope if we keep it on official APIs or a documented connector ({{STACK_OR_TOOL}} or equivalent) and we write down how someone else reruns it.

What I would deliver:
- A short map of the current process and the stop conditions
- The workflow with retries and a failure path
- An operator SOP (what breaks, how to rerun, where secrets live)

I will not move chat or payment off Upwork before a contract.

Could you confirm:
1. {{QUESTION_1}}
2. {{QUESTION_2}}

If that matches, I can send a milestone outline here.
```

## If they already asked for WhatsApp in the invite

Do not argue at length. Use snippet 08 block C (Upwork), then continue scoping on-platform if they stay.
